# 전체 Split 작업 목록과 자원 사전 검증

## 1. 범위와 완료 판정

2026-10-20, InventoryEngine `inventory_engine_dev`의 로컬 Offline 사전 검증이다.
공식 2037/2044 Source·경로·선정 결과를 생성하지 않는다. 기존 FSN·운영 Gate·DB·공용 Runtime도 변경하지 않는다.
기존 원문/결과 Hash와 V1/V2/V3·원문 20GB·호출당 3,600초 계약을 유지한다.

작업 목록의 완전성, 수작업 사례의 실제 실행, 전체 규모의 부분 추정을 분리한다.
미측정 작업은 `null`과 차단 사유로 남기며, 부분 추정이 20GB 안에 들어도 전체 실험을 허용하지 않는다.
이 계약은 업무 정책의 성과나 운영 적격을 승인하는 계약이 아니다.

## 2. 공식 입력을 만들지 않는 전체 작업 목록

[고정 Protocol](data/catalog-robustness-protocol-v1.json)의 원 Hash를 확인한 뒤
[작업 목록 생성기](../../src/dsio_inventory_engine/evaluate_replenishment/robustness/split_preflight.py)가 메타데이터만 전개한다.
원 Protocol의 상태·날짜·Seed·후보 범위·Hash는 수정하지 않는다.

| 구분 | 작업 수 | 의미 |
|---|---:|---|
| 기본 WIDE Bank | 198 | 2개 Window × 3품목 × (Nominal 1 + Selection 8 + Validation 8 + Holdout 16) |
| Stress WIDE Bank | 16 | 2개 Window × 간헐수요 2품목 × Stress 4종 |
| 독립 시간 비교 | 27 | ROBUST-A의 3품목 × 3개 방식 × 순환 실행 3회 |
| 종료 효과 재생 상한 | 180 | 2개 Window × 3품목 × 3개 방식 × 5개 비용 Profile × 2개 선정 방식 |
| 전체 작업 상한 | 421 | 실제 선정 정책 중복을 제거하기 전의 상한 |

기본·Stress Bank는 각각 88개 전체 후보를 실행할 계획이다. ABC/XYZ·LEGACY_STYLE 범위와 5개 비용 Profile에
기본 Bank를 재사용하므로 이를 다시 곱해 PSI 횟수를 부풀리지 않는다. 시간 비교의 27개 작업은 방식 간 Bank를 공유하지 않는다.
종료 효과 재생은 선정 후 잠긴 정책만 대상으로 하며, 52주 단일 정책 재생이다. 65주 결과는 Validation Bank를 재사용한다.
180개는 실제 확정된 정책 수가 아니며, 아직 Candidate ID를 정하거나 Holdout에서 재선정하지 않는다.

후보×주차 작업량은 기본 1,132,560, Stress 91,520, 시간 비교 88,920, 종료 재생 상한 9,360이다.
이는 실제 CPU 명령 수나 실행시간이 아니다. 작업 목록도 실행 순서가 아니라 의존조건을 가진 목록이다.
Holdout/종료 재생의 선정 Lock, Task 중복·누락·Seed/Window/후보 변경을 검증한다.

## 3. 같은 관리 루트에서 측정하는 로컬 진입점

[측정 UseCase](../../src/dsio_inventory_engine/evaluate_replenishment/robustness/split_calibration.py)는
기존 [ControlledCatalogExecutor](../../src/dsio_inventory_engine/evaluate_replenishment/robustness/resource_execution.py)를 사용한다.
폴더별로 예산을 새로 만드는 것이 아니라 하나의 `LocalRobustnessResourcePool`을 모든 방식·반복에서 공유한다.
기존의 원문 예산 예약, Worker 중단, Hash 검증, 24시간 임시 파일 격리를 그대로 거친다.

측정 입력은 기존 2055-01-04, `HAND-CATALOG-PATH`, Seed 71, Nominal 65주 수작업 사례로 제한한다.
공식 날짜/Path·부분 후보 목록·미확인 결과 Hash·V1/V2 측정 요청은 이 진입점에서 거부한다.
실제 영속 조립기→수학 전략→공통 Guard→PSI→원 Artifact 저장을 실행한 뒤,
무결성 조회의 `NOT_RUN`과 전체 재계산의 `VERIFIED`를 구분한다. 성공 후보 수·PSI Row·기존 결과 Hash를 확인한다.

- 32/32/88개 전체 후보와 2,080/2,080/5,720 PSI Row를 줄이지 않는다.
- `run`, `inspect`, `verify_recalculation` 시간과 자원 대사를 포함한 호출 전체 시간을 별도로 기록한다.
- 관리 루트의 원문/물리 바이트·파일 수 증가분에는 실제로 보존된 Job 격리 파일도 포함한다.
- 이미 사용한 측정 폴더는 거부한다. 멱등 재사용의 0 Byte 증가분을 새 계산의 저장량으로 위장하지 않는다.
  중단된 원 Artifact의 복구는 기존 정확한 입력 Hash 기반 `recover` 계약이며, 미완료 측정을 성공 표본으로 사용하지 않는다.

[개발 측정 스크립트](../../scripts/preflight_robustness_split.py)는 테스트용 수작업 Source Factory만 연결한다.
설치된 공용 업무 Runtime이나 Platform 실행 API에 공식 Split 실행을 활성화하는 변경은 아니다.
동일한 명시적 빈 전용 루트를 사용하며, 다른 사용자 디렉터리·기존 결과를 초기화하거나 삭제하지 않는다.
소스/Fixture 지문을 전후 대조하고 실행 순서를 회전한다. 실제 DB 연결과 Forecast 재실행은 없다.

## 4. 추정·미측정·실제 한도를 구분한다

새 별도 응답과 [JSON Schema](../../schemas/robustness_split_preflight.schema.json)는
`inventory-robustness-split-resource-preflight` `1.0.0`이다. 원 PSI나 결과 Artifact를 변경하지 않는다.

- 같은 관리 루트의 3개 방식 표본이 모두 필요하다. 반복값은 방식별 각 자원의 최대값을 사용한다.
- 측정 가능한 241개 Catalog 작업에 대한 부분 추정과 25% 여유를 더한 값을 나눈다.
  25%는 개발 자원 산정의 가정이지 통계적 상한·재고정책 계수가 아니다. 25~100%에서 늘릴 수 있으며 낮추거나 비활성화하지 않는다.
- 원문·물리 크기를 분리한다. 압축 크기로 20GB 원문 예산을 판정하지 않는다.
  물리 크기는 파일 내용 바이트의 합계이며 파일시스템 블록 할당량이나 호스트 여유 공간 보증은 아니다.
  파일 수와 Bank 호출 전체 시간도 별도로 확인한다. 3,600초는 전체 실험 완료시간이 아니다.
- 표본 측정값의 일관된 Hash는 출처의 업무 권위나 미래 전체 입력의 최대 크기를 보증하지 않는다.
  큰 루트의 새 프로세스 대사 비용을 작은 루트와 같은 상수 비용으로 간주하지 않는다.

다음 여섯 항목은 실제 측정이 없으므로 전체 원문/물리 크기·파일 수·시간을 `null`로 유지한다.

기존 순수 비용/선정 평가기와 Warm-up Source가 미구현이라는 뜻은 아니다. 이를 전체 Split의 입력·선정 Lock·
저장/재시작에 연결했을 때의 비용과, 새 52주 단일 정책 진입점의 비용이 아직 확인되지 않았다는 뜻이다.

1. 선정 Lock에 연결된 단일 정책 52주 종료 효과 재생
2. 범위 Projection·비용 재계산·선정·전체 Split Manifest 조립
3. 데이터가 쌓인 관리 루트의 대사와 새 프로세스 비용 증가
4. 실제 실험 품목·경로에 따른 크기 차이
5. 중단·격리·Retry에 필요한 추가 여유
6. 공식 Source 생성·전체 품목 분류

현재 응답은 `BLOCKED_INCOMPLETE_MEASUREMENTS`다. 알려진 부분 추정만 한도를 넘으면 별도 사유도 추가한다.
누락 값을 0으로 바꾸거나 후보/기간을 줄여 합격시키지 않는다. 공식 경로 생성·실험 실행·자동 게시·발주·DB Write는 모두 허용하지 않는다.
실제 전체 실행에는 기존 관리 루트의 매 게시 시점 한도가 계속 적용된다. 이 추정값이 한도를 대체하지 않는다.

## 5. 검증과 증적

수작업 산술, 전체 작업 수/식별자, 누락/중복·계약 변조, 모드 누락, 다른 Pool 표본,
압축 예산 우회, 파일 수/전체 호출 여유, 미측정 0 채움과 승인 상태 위조를 검증한다.
실제 Offline 계산은 세 방식 모두 같은 Pool에서 실행하며 원 Source·분류·Gate·결과 Hash를 보존한다.

별도 2회 순환 실측의 방식별 결과는 다음과 같다. 호출 시간은 계산·조회·전체 재계산과 자원 대사를 포함한다.

| 방식 | 원문 증가 MB | 물리 증가 MB | 호출 시간 초 |
|---|---:|---:|---:|
| ABC/XYZ 32개 | 22.996 | 2.352 | 23.64~27.99 |
| LEGACY_STYLE 32개 | 22.993 | 2.366 | 24.69~26.54 |
| WIDE_REFERENCE 88개 | 60.763 | 5.983 | 65.75~66.38 |

알려진 Catalog 부분 추정은 원문 13.964GB·물리 1.377GB·36,497개 파일·약 4.25시간이다.
개발 여유 25% 포함 값은 원문 17.455GB·물리 1.721GB·45,622개 파일·약 5.31시간이다.
이는 작은 수작업 표본의 환산이며 전체 합계·하드 상한·운영 성능 보증이 아니다.
실제 측정 루트는 원문 213,504,564 Byte·물리 21,402,050 Byte·883개 파일과 Job 격리 18개를 보존했다.
CLI 종료 코드 `2`는 실측 오류가 아니라 미측정 항목 때문에 전체 실행 가능 판정이 차단됐다는 뜻이다.

실측값·최종 회귀·소스 지문·보존 대사는 [검증 기록](evidence/robustness-split-preflight-20261020.json)에 기록한다.
새 단위 38건·계약 14건·Offline 통합 7건의 대상 회귀는 **59 passed**(115.60초)다.
소스를 고정한 전체 회귀는 **1,796 passed / 9 skipped / 669 subtests passed**(1,196.83초), 기존 Starlette 경고 3건이다.
Ruff·Format 365개 파일·JSON Schema 40개·선택한 여섯 문서의 로컬 참조 149건·Diff Check를 통과했다.
승인된 기존 문서 3개 외에 기존 보호 파일 541개와 개인 보고서는 동일하다. 기존 코드·규칙·Schema·Golden·측정 기록을 보존했다.
스킬 공통 참조와 `oma docs` CLI가 없어 저장소 검사와 직접 참조 대사로 보완했다. Coverage·Bandit·Mypy·독립 에이전트 검토는 수행하지 않았다.
고정 성능 개선율·프로세스 RSS 제한·20GB 전체 적재·3,600초 실제 대기·공식 정책 성과를 주장하지 않는다.
